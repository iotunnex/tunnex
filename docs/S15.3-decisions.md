# ⛔ 0. THE RENDER FLOOR. FIRST, BEFORE ANY COPY.

Read from `docs/EPIC-15-zero-trust-for-ai-agents.md` §0 before a word of this paper's copy was written.

> ## **UNDER PROMPT INJECTION, AUTHENTICATION IS INTACT AND AUTHORIZATION IS INTACT. ONLY *INTENT* IS
> ## CORRUPTED. ZERO TRUST BOUNDS THE BLAST RADIUS OF A CORRECTLY-AUTHENTICATED PRINCIPAL. IT DOES NOT
> ## DETECT INJECTION.**

**Two claims this surface may never make, in any copy, at any size:**

| forbidden claim | why |
| --- | --- |
| ⛔ **detection** — "catches", "blocks", "prevents" a manipulated request | The product does not inspect intent. A boundary **limits what a request can reach**; it does not know the request was manipulated. Claiming otherwise is a render-floor violation **at product scale** — a promise made to people who cannot check it |
| ⛔ **per-tool control** — "allow this agent to call *this MCP tool*" | Enforcement is **five fields**: `SrcIP, DstCIDR, Protocol, PortLow, PortHigh`. A tool name is not among them and cannot be. Teleport does per-tool; **we do not**, and the claim is checkable and false |

⚠ **The honest verb is REACH.** This surface says *which agents may reach which destinations*. It never says
*which actions they may perform there*, because the enforcement plane cannot see actions.

**Permitted, because they are true:** *bounded* · *reachable* · *attributable* · *revocable* · *unattributable*.

# 1. ⛔ THE HARD CONSTRAINT — NOTHING HERE REACHES THE COMPILED ARTIFACT

`hashAllow` is **`{SrcIP, DstCIDR, Protocol, PortLow, PortHigh}`** (`policyspec/hash.go:15-21`), and
**`dst_kind` never reaches the agent.** That is the epic's central measured finding, and it cuts both ways:

- it is why the **destination half already shipped** — an MCP server is expressible today;
- it is why **a new marker is invisible to enforcement by construction.**

> ## **THIS SURFACE IS A NAMING AND PRESENTATION LAYER OVER WHAT ALREADY SHIPS. IT IS NEVER A SECOND
> ## ENFORCEMENT PATH.**

⛔ **If a design requires touching `policyspec`, it is the wrong design and it returns as a decide-item.**
The test is mechanical: **does `make generate` change `CanonicalHash` inputs?** If yes, stop.

⚠ **And this is a gift, not a limitation.** A marker outside the compiler cannot desync the artifact, cannot
bump `RequiredVersion`, and cannot brick a gateway that has not been updated. **The cheapest place to be wrong
is outside the thing that must be right.**

# 2. WHAT ALREADY EXISTS — MEASURED FROM THE SCHEMA AND THE SERVED PAYLOAD

**More than expected. Most of the surface's raw material is already shipped and reachable.**

## 2.1 Persisted AND served today

| fact | where | reachable via |
| --- | --- | --- |
| **`nodes.owner_user_id`** | S15.2 `0066` | ✅ `GET /organizations/{id}/nodes` |
| **`nodes.owner_email`** — resolved from `users`, survives the owner leaving the org | S15.2 / D22 | ✅ same payload |
| ⭐ **`nodes.unattributable`** — the degraded state, already a boolean on the wire | S15.2 / D25(C) | ✅ same payload |
| `machine_credentials.user_id` + `owner_email` | S15.1 | ✅ `GET .../machine-credentials` |

⭐ **The `nodes` DTO already carries owner, owner email AND unattributable.** A screen that lists agents with
their owners and flags the degraded ones **needs no new API field at all** — verified against the live payload,
not the spec.

## 2.2 Persisted but **NOT SERVED** — the gap

| fact | where | problem |
| --- | --- | --- |
| ⛔ **`devices.kind = 'agent'`** | S15.2 `0067` | **Not in the device DTO.** Served keys are `approved_by, created_at, health_*, id, name, needs_reexport, node_id, online, platform, public_key, status, user_id` — **no `kind`** |
| `node_join_tokens.issued_by` | S15.2 `0066` | not served anywhere |
| `RoleAgent` | `rbac.go` | in the grant table; not exposed per-principal |

⛔ **THE AGENT MARKER EXISTS IN THE DATABASE AND IS INVISIBLE TO EVERY CLIENT.** This is the who-reads-this
probe failing on a column S15.2 added — the same defect as `owner_email` in S15.1, one table over. **A device
list cannot distinguish an agent from a laptop.**

## 2.3 Does NOT exist

⛔ **An MCP server is INDISTINGUISHABLE from any other port-scoped resource.** Served resource keys are
`cidr, created_at, id, name, org_id, port_high, port_low, protocol, updated_at` — **no type, kind, or label.**
Confirmed, as expected.

**The cheapest honest marker:** a **nullable free-text `kind` (or `label`) on `resources`**, set by the
operator, defaulting to NULL.

- ⚠ **It must be an operator's assertion, never an inference.** The product cannot detect that something
  speaks MCP. A field that *claims* detection would be §0's violation in miniature. The copy is *"what is
  this?"*, answered by a human.
- ⛔ **It lives entirely outside the compiler.** `resources` feeds `dst_cidr/protocol/port_*` into
  `hashAllow`; a `kind` column is simply not read by the compiler, so it cannot reach the artifact **by
  construction rather than by discipline.**
- ⚠ **Enum or free text is a decide-item** (§5.2). An enum is greppable and constrains copy; free text does
  not require a migration every time a new protocol appears.

# 3. WHERE IT BELONGS IN THE NAV — **ARGUED, NOT CHOSEN**

Current sidebar: **Overview · Gateways · Sites · Routed ranges · Kubernetes · Access Policies · Devices ·
Users & Roles · Access Events · Audit Log · Org Settings.**

> ## **A NEW DESTINATION IS A CLAIM ABOUT HOW THE PRODUCT IS ORGANISED**, not a place to put a screen. The
> ## sidebar's current claim is *by resource type* (gateways, sites, devices, clusters) plus *by
> ## cross-cutting concern* (policies, events, audit).

| option | the claim it makes | against it |
| --- | --- | --- |
| **A — a new top-level "AI Agents"** | agents are **a first-class thing an operator manages**, peer to Devices | ⚠ a twelfth item on a sidebar already at eleven; and an agent **is** a gateway + a device row, so it risks being a *view* masquerading as an *entity* |
| **B — a section inside Devices** *(recommended)* | an agent is **a kind of device**, which is **exactly what the schema says** (`devices.kind`) | less discoverable; "Devices" reads as human endpoints today |
| **C — a section inside Gateways** | an agent is a gateway that carries a principal | ⛔ conflates the *machine* with the *principal*; a gateway can host an agent and human peers at once |
| **D — a panel on Access Policies** | agents are a policy concern | ⛔ answers *what may they reach* while making *which agents exist* unanswerable |

**RECOMMENDATION: B, with a filter and a distinct empty state** — because the model already says an agent is
a `devices` row, and **B is the only option that does not invent an organising principle the schema does not
have.** ⚠ A is defensible **if** the founder judges that *naming the feature* outranks structural honesty —
that is a marketing-vs-model tradeoff and it is the founder's call, not a design detail.

⛔ **Not chosen. §5.1.**

# 4. WHAT THE SCREEN MUST SAY — from real data, and the floor it must not cross

**Must, and all four are answerable from data that exists today:**

| claim | source |
| --- | --- |
| **which agents exist** | `devices.kind='agent'` (needs serving) + `nodes` |
| **who owns each** | `nodes.owner_email` — **already served** |
| ⛔ **which are unattributable, and therefore degraded** | `nodes.unattributable` — **already served** |
| **which destinations they may reach** | the compiled allow-set / policy rules, already rendered on Access Policies |

**Must not:**

- ⛔ **no per-tool control**, in any wording (§0);
- ⛔ **no detection language** — the screen reports *state*, never *interception*;
- ⚠ **no "secure"/"protected" verdict.** A bounded agent is bounded, not safe. The nearest true word is
  **reachability**, and it should be used literally.

⚠ **AND THE DEGRADED STATE IS THE MOST IMPORTANT THING ON THE SCREEN**, because it is the one an operator
cannot get anywhere else: an unattributable agent **still works** and its activity **cannot be tied to a
person.** That is a live audit gap with a name.

# 5. DECIDE-ITEMS — **HELD. No product code until ruled.**

### 5.1 Nav placement — A, B, C or D?
**Recommend B.** ⛔ The tradeoff is *naming the feature* (A) versus *not inventing an organising principle the
schema lacks* (B).

### 5.2 The resource marker — enum or free text? And is `kind` the right word?
**Recommend a nullable free-text `label`.** ⚠ `kind` collides with `devices.kind`, which is a *structural*
discriminator carrying the cap exemption; this one is **descriptive and carries nothing.** Two columns named
`kind` with different force is how the next reader gets it wrong.

### 5.3 ⛔ **RULED: SERVE `devices.kind`.**

**The reason:** the alternative is worse than a contract change — **a column persisted by the story that
added it and read by nobody.**

> ## **THAT IS THE SECOND INSTANCE IN TWO STORIES** — `owner_email` (S15.1) and `kind` (S15.2), each
> ## persisted by the story that added it and served by neither. **Shipping a third would make it a habit
> ## rather than a class.**

#### ⚠ THE CONTRACT CHANGE, STATED HONESTLY RATHER THAN BURIED AS "ADDITIVE"

**Every device payload widens, including consumers that never heard of agents.** ⛔ *Additive* is a property
of the schema, not a guarantee about consumers — so the consumers are named and measured:

| consumer | what it does with an unknown field | measured |
| --- | --- | --- |
| **`apps/cli`** — generated Go client (`apps/cli/internal/api/api.gen.go`) | **ignores it.** `encoding/json` is permissive by default and **`DisallowUnknownFields` appears nowhere in the repo** | grep: zero hits |
| **`packages/shared`** — generated TS types (`api.d.ts:2639`) | **structural types only.** An extra property is present at runtime and unreferenced; no runtime validator sits between | read |
| **the API's own response path** | **no response validation** — the middleware validates *requests* against the spec, not responses | grep: zero hits |
| **`apps/web`** | regenerated from the spec in the same commit; a field it does not render is inert | — |

⚠ **So the blast radius is genuinely nil — and it is nil for a REASON, not by assumption.** Had any consumer
used strict decoding, this would have been a breaking change wearing the word *additive*.

### 5.4 ⛔ **RULED: NOT ENTERPRISE-GATED.**

**The reason:** this surface **describes behaviour that ships in BOTH editions.** Gating a description of
open-edition behaviour **hides the product from the people running it.**

⚠ **AND THE SHAPE IS ONE THIS REPO HAS ALREADY PAID FOR.** S14.5 found the open edition shown an **upsell for
an all-editions capability** — a client-invented boundary the server does not have.

> ## **GATING THIS WOULD BE THAT DEFECT, DELIBERATELY.** The edition boundary is the server's to state; a
> ## surface that invents one is lying about the product in the direction of a sale.

### 5.4 Is this enterprise-gated?
⚠ **Unlock-then-opt-in is the standing convention**, but this surface *describes* what already ships in both
editions. **Gating a description of open-edition behaviour would hide the product from the people running
it.** Recommend **not gated**; flagged because the convention exists.

# 6A. ⚠ A NOTE THE FIXTURE REWRITE EARNED — it is about fixtures, not trivia

While fixing the peer-key fixtures (15 files), **the rewrite itself introduced two regressions**, and both
were caught **only because the tests they broke were pinning something real.**

| regression | what it destroyed |
| --- | --- |
| ⛔ **a KEYLESS OVPN device was given a key** | **the fixture's EMPTINESS *was* the assertion.** An OpenVPN client carries a cert, not a WG key; giving it one makes it a peer — the precise invariant those tests exist to pin |
| an email prefix (`"pk-"+id+"@ex.com"`) rewritten as a key | nothing functional; it made a fixture nonsense |

> ## **A FIXTURE REWRITE IS A CHANGE TO WHAT THE TESTS ARE ABOUT.** It looks mechanical and it is not: a
> ## rewriter that treats every key-shaped field as a key **destroys the cases whose whole content is that
> ## the field is ABSENT.**

⚠ **Directly relevant to §6:** this story seeds agent fixtures, and **the states that matter most are
absences** — an agent with **no owner** (unattributable), an agent with **no reachable destinations**. **A
fixture generator that fills every field would erase exactly the states the screen exists to show.**
