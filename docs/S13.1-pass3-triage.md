## E. AN OBSERVATION RAISED BY THE TRIAGE, not in the 52

`saveCreds` (`main.go:453`) writes in the order `ca.pem`, `cert.pem`, `key.pem` — key last — and the comment
vouches: *"if the sequence is interrupted, the old key still matches the old certificate and the agent remains
recoverable."* **But `cert.pem` has already been replaced by then**, so an interruption between the second and
third rename leaves NEW cert + OLD key — the mismatch the ordering exists to prevent. Either ordering leaves a
mismatched pair; the question is which mismatch is recoverable. **Flagged for verification, not asserted** — this
was reasoned from the code in one pass and has no red.
