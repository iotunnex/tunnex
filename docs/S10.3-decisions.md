## Verify pass — mechanisms found (the design is mostly reuse)
- **Exposed Service → resource shape, resolved from identity.** A VIP/32 : proto : ports fits the
  `resources` wire shape (`0018_zero_trust.up.sql:51-65`), but the resource path carries a LITERAL,
  never-re-resolved CIDR (`compiler.go:385`) — fatal under VIP reassignment. So an exposed Service is a
  NEW entity resolved to the CURRENT VIP at compile, mirroring the device-source ruling
  (`ListActiveDevicesForOrg` `policy.sql:139-154` → `groupDeviceIPs` `compiler.go:254-276`).
- **VIP allocation reuses `ipalloc.Allocate` unchanged** (`ipalloc.go:32-58`, pure + CIDR-agnostic — a VIP
  range is a second `cidr` arg with its own used-set).
- **DNAT = a genuinely-new `prerouting dstnat` chain** in `table ip tunnex` (today only postrouting/srcnat),
  rendered into the atomic `add;flush;table` full-replace (`egress_linux.go:394-414`) → keyed + swept for
  FREE (no handle bookkeeping). NET_ADMIN already granted; no new capability.
- **DNS-rewrite = small.** A response-mutation at `dnsforward.go:169` (swap A-record ClusterIP→VIP via the
  already-imported `dnsmessage` codec) + a VIP↔ClusterIP map threaded `SetTable`-style. No new daemon.
- **DesiredState carrier** — a new out-of-hash `omitempty` VIP map on `policyspec.Compiled`/`nodepolicy.Compiled`
  (mirror `DNSForwards`/`PoolCIDR`), stapled in `finalizeArtifact` (`nodes/service.go:1253`), consumed in the
  agent `OnPolicy` fan-out (`main.go:182-189`) → egress (DNAT) + dnsFwd (rewrite). Apply-on-change/
  sweep-on-removal free via the atomic egress replace + atomic `SetTable` rebuild.

## Sub-forks — ruled on merit (delegated judgment; flag to redirect)
- **F1 — exposed Service = NEW entity** (`k8s_service`: cluster/site, name, namespace, proto, ports; VIP
  allocated), NOT a plain `resources` row. RULED new-entity — it is the only VIP-reassignment-safe shape and
  it realizes the founder's condition 3 (identity-resolution at compile). It is a DESTINATION with a stable
  ID, not a source principal — does NOT touch D4(a)/the identity-binding invariant.
- **F2 — subnetguard registration.** RULED: add a typed **`ClassVIPRange`** (symmetric with site/pool, honest
  error text — matches "allocator-known + subnetguard-validated"), NOT fold-into-`reserved`. **Law rider:**
  every `Check` caller (pool-resize, site-approval, cluster-VIP-range creation) must feed the org's VIP ranges
  into its input set so disjointness stays BIDIRECTIONAL (the validator-input-filtering law, S8.1). This is a
  new instance of that law — noted.
- **F3 — VIP-map version discipline.** RULED **PoolCIDR-style** (content-derived `RequiredVersion` bump,
  refuse-not-silent), NOT DNSForwards-style (convenience, no trigger). A VIP→ClusterIP DNAT an old agent
  silently ignores = the exposed Service is DEAD-WHILE-GREEN — the exact PoolCIDR/Routes failure mode
  (`policyspec.go:88-92`). New `ProtocolVersion` 6→7, triggered only when the VIP map is non-empty (non-K8s
  orgs stay byte-identical).
- **F4 — hostNetwork.** RULED **required** for the gateway pod: the agent's `prerouting` DNAT (VIP→ClusterIP)
  must chain into kube-proxy's ClusterIP→pod DNAT, which lives in the node/host netns — so the agent's
  nftables must sit there. hostNetwork also inherits the node `ip_forward` + gives the real WG datapath.
  (Resolves the thread-B open item.)
- **F5 — join token.** RULED support both `joinToken` (chart mints the Secret) + `existingJoinTokenSecret`
  (operator pre-creates), PREFER existingSecret — the CP master-key posture (a token in helm history leaks).
- **F6 — endpoint chicken-and-egg.** RULED operator-supplied `endpoint` REQUIRED (a `required` guard); the LB
  external IP may not exist at install, so the operator reserves/knows it (or a static `loadBalancerIP`). This
  is a PD-4-style fabric promise the chart can't synthesize.
- **F7 — preflight mechanism.** RULED **(a) a pre-install,pre-upgrade hook Job** requesting the privileged/
  hostNetwork/NET_ADMIN/`/dev/net/tun` context + self-asserting → on a blocking cluster the Job pod is
  admission-REJECTED, so `helm install --wait` fails at the hook before the real Deployment (no crash-loop) —
  the guard-before-exec doctrine (`ovpnserver.go:112`). Complement with **(b)** a `required` privilege-ack
  value. Reject (c) (surfaces too late). NOTES mandates `--wait`.

## Slice 1 — VIP-stability disposition (RULED, condition from the F2/D3-condition-3 blessing)

The reassignment hazard is born in ExposeService's allocation. **RULED: identity-resolution alone is
sufficient — allocation does NOT quarantine freed VIPs, and this is safe by construction.** The used-set
(`ListUsedVIPsInCluster`) is LIVE Services only, so a soft-deleted Service's VIP is immediately reusable.
That is safe because a grant references a Service's STABLE ID and the compiler resolves ID → CURRENT VIP
at compile time and **NEVER caches a VIP** (Slice 2): a deleted Service vanishes from the resolution set
(its grant compiles to nothing), and a reused VIP belongs unambiguously to the NEW Service's identity. No
quarantine timer is needed (the rejected alternative — complexity for no gain once grants track identity).
The **reassignment-trap red belongs in Slice 2** (where the resolution is built): prove a deleted Service's
grant compiles to nothing AND a re-exposed Service reusing the freed VIP resolves to the NEW identity only.
