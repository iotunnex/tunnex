| Component / Panel | Verdict | Rationale |

| **Header & Title (`<h1 ...>`, Subtitle)** | **(a) Functional render floor** | Title MUST be `<h1 style="...">Devices</h1>` so `getByRole("heading", { name: "Devices" })` and Playwright/A11y tests resolve it. | **Devices DataTable (`caption="Devices"`)** | **(a) Functional render floor** | Table with 5 canonical column headers (`Device`, `Address`, `State`, `Posture`, `Actions`). |
| **- Device Name Cell** | **(a) Functional render floor** | Renders `d.name` text. |
| **- Address Cell** | **(a) Functional render floor** | Renders `d.assigned_ip` in `JetBrains Mono`. |

## 2. Status Representation (`active` | `revoked` | `pending`), `health_blocked`, and `approved_by`

- **`status` Enum (`active`, `revoked`, `pending`):**
  - `active`: Normal functioning device. Renders `StatusDot` (on/off) and `lastSeen(...)`. Shows `Revoke` button.
  - `revoked`: Device revoked. Renders `<Badge tone="danger">revoked</Badge>`. Posture badges, `re-export needed`, and actions are **SUPPRESSED** via `d.status !== "revoked"`.
  - `pending`: Device awaiting admin approval under Enterprise device approval mode. Renders `<Badge tone="warn">pending</Badge>`. During issuance ceremony, `pendingExport` surfaces: *"This device is pending approval - the profile is valid but won't connect until an admin approves the device."*
- **Tone Vocabulary & `BadgeTone` Primitive Extension:**
  - `Gateways.tsx` line 310 uses `<Badge tone="warn">` for degraded node warning states.
  - `Devices.tsx` uses `<Badge tone="warn">pending</Badge>` for pending approval state.
  - **Shared Primitive Widening:** `BadgeTone` in `apps/web/src/components/ui.tsx` has been widened:
    ```typescript
    export type BadgeTone = "ok" | "warn" | "danger" | "neutral" | "unknown";
    ```
  - Posture cells in `Devices.tsx` render posture badges using the shared `<Badge>` primitive (`<Badge tone={pb.tone}>{pb.label}</Badge>`), ensuring posture badges are fully accessible and queryable by badge-level selectors.
- **`<Badge>` Component AST Call Site Census (19 Component Invocations):**
  - `IdentityBadges.tsx:60, 61`: 2 neutral badges
  - `Dashboard.tsx:516`: `<Badge tone={g.tone}>{g.label}</Badge>` (where `g.tone` $\in$ `"warn" | "danger" | "unknown"`)
  - `Dashboard.tsx:791`: `<Badge tone="neutral">GEN {hv.generation}</Badge>`
  - `Devices.tsx:375, 377, 397`: 3 badges (`revoked` [danger], `pending` [warn], posture [tone])
  - `Gateways.tsx:132, 151, 155, 310`: 4 badges
  - `Kubernetes.tsx:251, 325`: 2 badges
  - `Sites.tsx:395, 869, 884, 888`: 4 badges
  - `VisualGallery.tsx:86, 119`: 2 badges
- **`health_blocked: true`:**
  - Enforcement fact: Device is excluded from every gateway while `true`. When `health_state === "noncompliant"` and `health_blocked === true`, renders `"posture blocked"`. Tested positively on `blocked-device`.
- **`approved_by: null` (Grandfathered):**
  - `approved_by: null` indicates a grandfathered / auto-approved device enrolled when device approval mode was off. Functions as active without requiring device approval queue action.

## 4. Control Plane Status Header Pattern Audit

- `HealthStatus` (`control plane operational` / `control plane unreachable`) already exists in `AppShell.tsx` (line 322) and renders in the footer of EVERY page after querying `/healthz`.
- Hardcoding static text `control plane ● healthy` in individual page title headers (`Access.tsx`, `Devices.tsx`) is a **NEW, ad-hoc pattern** that multiplies the registered duplicate-render defect across screens and desyncs from live `/healthz` telemetry.
- **Rule:** Page headers MUST NOT hardcode static `control plane ● healthy`. Page titles render `<h1 ...>Devices</h1>` with org subtitle `{org.name}`. Shell-level footer owns control plane health.
