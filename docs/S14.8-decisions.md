# 3. THE LIVE SCHEMA, AND ONE THING IT CONTRADICTS

```
k8s_clusters:  id, org_id, site_id, name, vip_range, created_at, updated_at,
               service_cidr, dns_zone, dns_vip, managed_by_machine
k8s_services:  id, org_id, cluster_id, name, namespace, protocol, port_low, port_high,
               vip, created_at, updated_at, deleted_at, managed_by_machine
```

**⚠ THE COLUMN IS `managed_by_machine`; THE API FIELD IS `managed_by_operator`.** `toAPIK8sCluster` maps one
to the other (`ManagedByMachine.Valid`). A reader who greps the schema for the field name the UI consumes
finds nothing — the same shape as `org_hub_set.members` vs `configured`, which cost a fixture error in S14.5.
**Recorded here so the next reader does not re-discover it.**

**`k8s_services.deleted_at` EXISTS**, so Services are soft-deleted. **Does the screen show them?** Not
answered anywhere yet — a decide-item, not an assumption.
